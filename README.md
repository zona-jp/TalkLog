# TalkLog — リアルタイム会話文字起こし

Windows PC + Google Chrome で、**自分の声（PCマイク）**と**相手の声（共有したタブ／システム音声）**を
同時に取得し、話している途中からリアルタイムに文字起こしする静的 Web アプリです。

バックエンド不要。`index.html` / `style.css` / `app.js` の 3 ファイルだけで動作し、
GitHub Pages・Netlify・Vercel にそのまま置いて公開できます。

---

## 特長

- **低遅延表示** — `interimResults` を有効にし、発話の途中から文字が伸びていきます。確定前の文字は「認識中」として薄く表示し、確定した時点で正式な会話ログへ移します。
- **話者を完全分離** — 「自分」と「相手」で `SpeechRecognition` インスタンスを別々に持ち、1 つのエンジンに混ぜません。
- **相手の声を認識に流し込む** — `getDisplayMedia()` で取得した音声トラックを、`SpeechRecognition.start(MediaStreamTrack)` に対応した Chrome では認識エンジンへ直接入力します（対応状況は起動時に自動判定します）。
- **止まらない設計** — Web Speech API が自動終了しても、ユーザーが停止していなければ自動で再開します。指数バックオフと再開回数の上限で無限ループを防ぎます。
- **状態が一目で分かる** — マイク／PC音声／文字認識（自分・相手）の 4 つの状態表示と、音声入力レベルメーターを備えています。「音は来ているのに文字にならない」のか「そもそも音が来ていない」のかを切り分けられます。
- **ログの書き出し** — 全文コピー / TXT 保存 / CSV 保存（UTF-8 BOM 付き、Excel でそのまま開けます）/ クリア。
- **賢い自動スクロール** — 常に最新へ追従しますが、過去ログを読んでいる間は勝手に最下部へ戻さず、「最新へ」ボタンと未読件数を表示します。

## 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 11（Windows 10 でも動作します） |
| ブラウザ | **Google Chrome 最新版**（主対象） |
| 接続 | **HTTPS** または `http://localhost` |
| マイク | PC マイク（ヘッドセット推奨） |

- Chrome 向けに最適化しています。Edge でも動作する場合がありますが、**相手側の文字起こしは Chrome 最新版でのみ想定**しています。
- Safari / Firefox は対象外です。未対応の場合はクラッシュせず、「Google Chrome 最新版をご利用ください」という案内を表示します。
- `getUserMedia` / `getDisplayMedia` はセキュアコンテキストでのみ利用できます。**HTTPS か localhost 以外では開始ボタンが無効になります。**

## 使い方

1. 公開した URL（HTTPS）をブラウザで開く
2. **「文字起こし開始」** を押す
3. **マイクの使用を許可** する
4. Chrome の共有ダイアログで、**「Chrome のタブ」**（相手の声が出ているタブ）または **「画面全体」** を選ぶ
5. ダイアログ左下の **「タブの音声を共有」／「システム音声を共有」を必ず ON** にする
6. 「共有」を押すと文字起こしが始まります（すべて成功して初めて「文字起こし中」になります）

停止するときは「停止」を押します。Chrome の「共有を停止」バーから共有を止めた場合は、**相手側の認識だけが停止**し、自分側は継続します。

### 自分の声だけを記録したいとき

ツールバーの **「相手の音声（画面共有）も文字起こし」** のチェックを外して開始してください。画面共有をスキップします。

## 注意事項

### Chrome の音声共有の仕様

Windows の Chrome では、共有対象によって音声を取得できるかが変わります。

| 共有対象 | 音声 |
|---|---|
| Chrome のタブ | **取得できる**（「タブの音声を共有」を ON にした場合） |
| 画面全体 | **取得できる**（「システム音声を共有」を ON にした場合） |
| ウィンドウ | **取得できません** |

「ウィンドウ」を選ぶと音声トラックが 0 本になるため、本アプリはその場で開始を中止し、原因を表示します。

### エコー（自分の声として相手の発言が混ざる）

スピーカーで相手の声を再生していると、マイクがそれを拾って「自分」として記録されることがあります。
**ヘッドホン／ヘッドセットの使用を推奨します。**

### 認識精度と対応言語

文字起こしはブラウザの Web Speech API に依存します。専用の書き起こしサービスと比べると、
固有名詞・専門用語・複数人の同時発話には弱く、句読点が付かない場合があります。
認識言語はヘッダーのセレクトボックスから切り替えられます（開始前に選択してください）。

### 相手側が「非対応」と表示される場合

お使いの Chrome が `SpeechRecognition` への音声トラック入力に対応していない場合、
音声自体は取得できていても文字起こしはできません（PC音声のレベルメーターは動作します）。
**Chrome を最新版へ更新してください。**

> 参考: どうしても相手側の文字起こしが必要な場合の代替として、Windows のサウンド設定で
> 「ステレオ ミキサー」などのループバック録音デバイスを**既定のマイク**に設定すると、
> 「自分」側の認識でシステム音声を拾えます。ただしその間は本来のマイク入力が使えず、
> 話者の区別もできなくなるため、あくまで暫定手段です。

## プライバシーについて

本アプリはサーバーを持たず、会話データをどこかへ送信・保存する処理を一切含みません。
文字起こし結果はブラウザのメモリ上にのみ保持され、ページを閉じると消えます。

ただし、文字起こしそのものは **ブラウザの Web Speech API** が担っています。

- **Chrome の Web Speech API は、多くの場合、音声データをブラウザベンダーのサーバーへ送信して認識処理を行います。**
- Chrome のオンデバイス音声認識モデルが利用可能な環境では端末内で処理されることがあり、本アプリは利用可能なら自動で有効化します（フッターに「エンジン: オンデバイス」と表示されます）。ただし、実際にどこで処理されるかはブラウザとその設定に依存し、本アプリ側では保証できません。

したがって、**「完全ローカル処理」「外部送信なし」とは言えません。**
機密性の高い会話に利用する際は、所属組織のポリシーをご確認ください。

また、画面共有を行うため、共有対象の画面内容が Chrome のキャプチャ対象になります
（本アプリは映像トラックを表示にも録画にも使用しませんが、取得はしています）。

## 公開手順

バックエンド不要・ビルド不要です。4 ファイルをそのまま配置してください。

```
index.html
style.css
app.js
README.md
```

### GitHub Pages

```bash
git init && git add . && git commit -m "Add TalkLog"
```

1. GitHub でリポジトリを作成し、push する
2. リポジトリの **Settings → Pages** を開く
3. **Source** を `Deploy from a branch`、Branch を `main` / `(root)` に設定して保存
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます（HTTPS）

### Netlify

サイト一覧の画面にフォルダをドラッグ＆ドロップするだけで公開されます（ビルド設定不要）。

### Vercel

リポジトリを import し、Framework Preset を **Other**、Build Command を空欄、Output Directory を `./` にします。

### ローカルで試す

`file://` では動作しません。ローカルサーバーを立ててください。

```bash
python -m http.server 8000
```

その後 `http://localhost:8000/` を開きます（localhost はセキュアコンテキスト扱いです）。

## 技術メモ

### ファイル構成

| ファイル | 役割 |
|---|---|
| `index.html` | 画面構造。外部ライブラリなし |
| `style.css` | Fluent Design 寄りの業務向け UI。ライト／ダーク自動切替、レスポンシブ |
| `app.js` | 全ロジック。外部依存なし・ビルド不要 |

### `app.js` の構成

| モジュール | 責務 |
|---|---|
| `Support` | ブラウザ対応状況の判定（セキュアコンテキスト / Web Speech API / トラック入力 / オンデバイス） |
| `AudioManager` | `getUserMedia` / `getDisplayMedia` の取得とトラック解放 |
| `LevelMeter` | Web Audio API による入力レベル表示（`AudioContext` は停止時に close） |
| `RecognitionEngine` | `SpeechRecognition` 1 系統分のラッパ。自動再開・バックオフ・エラー方針を内包 |
| `TranscriptStore` | 会話データの保持（`{ id, speaker, text, timestamp }`）と TXT / CSV 変換 |
| `TranscriptView` | DOM 描画。確定分は 1 件ずつ追加、暫定分は同一要素を書き換え、更新は rAF で 1 フレーム 1 回 |
| `StatusView` / `Alerts` / `Toast` | 状態表示と通知 |
| `Exporter` | コピー・ダウンロード |
| `App` | 開始フロー（STEP 1〜4）と全体制御 |

### トラック入力の判定方法

JavaScript は余分な引数を黙って捨てるため、単に `recognition.start(track)` と書くと、
未対応ブラウザでは「引数が無視されてマイクを聴き続ける」という最悪の誤動作になります
（相手の発言欄に自分の声が出続けます）。

そこで本アプリは、判定用インスタンスに **不正な引数** を渡し、
WebIDL の型変換で `TypeError` が同期的に投げられるかどうかで対応可否を判定しています。
判定はマイク許可の取得後に一度だけ行われます。

動作確認用に `?trackInput=on` / `?trackInput=off` で強制指定もできます。

### パフォーマンス上の工夫

- 暫定結果では要素を新規生成せず、既存要素の `textContent` のみ書き換える
- DOM への書き込みは `requestAnimationFrame` で 1 フレーム 1 回に集約する
- レベルメーターは変化が 2% 未満なら DOM を触らない
- 確定メッセージが 300 件を超えたら古い行を画面から間引く（保存・コピーには全件含まれます）
- イベントリスナーは要素ごとに 1 度だけ登録し、`SpeechRecognition` インスタンスは停止時に破棄する
- 停止時に `MediaStreamTrack` をすべて `stop()` し、`AudioContext` を `close()` する

### セキュリティ

認識結果を含むすべてのテキストは `textContent` で扱い、`innerHTML` へは代入しません（XSS 対策）。
