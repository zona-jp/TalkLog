# TalkLog — リアルタイム会話文字起こし

会話をリアルタイムに文字起こしし、**「自分」**と**「相手」**の発言を分けて表示するツールです。

```
自分   今日の進捗について確認してもいいですか？
相手   はい。昨日までに資料作成は完了しています。
自分   ありがとうございます。
相手   次の作業は明日から開始します。
```

バックエンド不要。`index.html` / `style.css` / `app.js` の3ファイルだけで動作し、GitHub Pages などにそのまま置いて公開できます。

**画面共有・タブ共有は使いません。** 開いて「文字起こし開始」を押すだけです。

---

## 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 11 / Windows 10 |
| ブラウザ | **Google Chrome 最新版** |
| 接続 | **HTTPS** または `http://localhost` |
| 音声 | PC マイク（＋相手の声用にループバック録音デバイス） |

`getUserMedia` はセキュアコンテキストでのみ利用できます。HTTPS か localhost 以外では開始ボタンが無効になります。

---

## 使い方

1. サイトを開く
2. **「文字起こし開始」** を押す
3. 初回のみ、**マイクの使用を許可**する
4. 会話を始めると、リアルタイムで文字が表示されます
5. 必要に応じて **コピー / TXT保存 / クリア**
6. 終わったら **「停止」**

これだけです。共有ダイアログも共有対象の選択も出ません。

---

## 「自分」と「相手」の区別について

TalkLog は**音の入り口を2つ使って**話者を区別します。声質の判定はしていません。

| 表示 | 音の入り口 |
|---|---|
| **自分** | PC のマイク |
| **相手** | PC で再生されている音（ループバック録音デバイス） |

「相手」側には Windows の **「ステレオ ミキサー」**（または VB-CABLE / VoiceMeeter などの仮想オーディオデバイス）を使います。アプリが起動時に自動で探して接続するため、ユーザー側の操作は不要です。

### 相手音声が「利用不可」と表示される場合

お使いの PC で「ステレオ ミキサー」が無効になっています。有効にすると相手の発言も文字起こしされます。

1. タスクバーのスピーカーアイコンを右クリック →「サウンドの設定」
2. 「サウンドの詳細設定」を開く
3. **「録音」タブ**を開く
4. 何もない場所を右クリック →「**無効なデバイスの表示**」にチェック
5. 「**ステレオ ミキサー**」を右クリック →「**有効**」
6. ブラウザのページを再読み込みして、もう一度「文字起こし開始」

ステレオ ミキサーが一覧に出てこない PC もあります（オーディオドライバが対応していない場合）。その場合は VB-CABLE などの仮想オーディオデバイスを導入するか、**自分の発言のみの文字起こし**としてご利用ください。相手音声が使えなくても、自分側の文字起こしは通常どおり動作します。

### ヘッドホンの使用を推奨します

スピーカーで相手の声を再生していると、マイクがその音も拾い、**同じ発言が「自分」としても記録される**ことがあります。ヘッドホンを使うとこの重複を防げます。

## 機能

- リアルタイム文字起こし（日本語 `ja-JP`）
- 発話の途中から表示される暫定結果（「認識中」として薄く表示し、確定したらログへ確定）
- 「自分」「相手」の区別と時系列表示
- 経過時間の表示
- マイク／相手音声の接続状態表示
- 全文コピー / TXT保存（UTF-8 BOM 付き）/ クリア
- 認識が自動終了しても自動で再開（無限ループ防止付き）
- 過去ログを読んでいる間は勝手に最下部へ戻らない（「最新へ」ボタンで復帰）

## 注意事項

### 認識精度

文字起こしはブラウザの Web Speech API に依存します。専用の書き起こしサービスと比べると、固有名詞・専門用語・複数人の同時発話には弱く、句読点が付かない場合があります。

### プライバシー

本アプリはサーバーを持たず、会話データをどこかへ送信・保存する処理を一切含みません。文字起こし結果はブラウザのメモリ上にのみ保持され、ページを閉じると消えます。

ただし、文字起こしそのものは **ブラウザの Web Speech API** が担っています。

- **Chrome の Web Speech API は、多くの場合、音声データをブラウザベンダーのサーバーへ送信して認識処理を行います。**
- 端末内で処理されるオンデバイス音声認識が利用可能な環境では自動で有効化しますが、実際にどこで処理されるかはブラウザとその設定に依存し、本アプリ側では保証できません。

したがって、**「完全ローカル処理」とは言えません。** 機密性の高い会話に利用する際は、所属組織のポリシーをご確認ください。

なお「相手音声」にループバック録音デバイスを使うため、**文字起こし中は PC で再生されている音がすべて認識対象になります**（会話以外の音楽や通知音も含む）。

## 公開手順

ビルド不要・バックエンド不要です。4ファイルをそのまま配置してください。

```
index.html
style.css
app.js
README.md
```

### GitHub Pages

1. リポジトリ**直下**に上記4ファイルを置いて push（ZIP のままでは展開されないので注意）
2. **Settings → Pages** を開く
3. **Source** を `Deploy from a branch`、Branch を `main` / `(root)` にして保存
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます（HTTPS）

### Netlify / Vercel

Netlify はフォルダをドラッグ＆ドロップするだけです。Vercel は Framework Preset を **Other**、Build Command を空欄、Output Directory を `./` にします。

### ローカルで試す

`file://` では動作しません。ローカルサーバーを立ててください。

```bash
python -m http.server 8000
```

その後 `http://localhost:8000/` を開きます。

## 技術メモ

| ファイル | 役割 |
|---|---|
| `index.html` | 画面構造。外部ライブラリなし |
| `style.css` | ライト／ダーク自動切替、レスポンシブ |
| `app.js` | 全ロジック。外部依存なし・ビルド不要 |

### `app.js` の構成

| モジュール | 責務 |
|---|---|
| `Support` | 対応状況の判定（セキュアコンテキスト / Web Speech API / トラック入力 / オンデバイス） |
| `AudioManager` | マイクとループバック入力の取得・デバイス検索・解放 |
| `RecognitionEngine` | `SpeechRecognition` 1系統分のラッパ。自動再開・バックオフ・エラー方針を内包 |
| `TranscriptStore` | 会話データの保持（`{ id, speaker, text, timestamp }`）と TXT 変換 |
| `TranscriptView` | DOM 描画。確定分は1件ずつ追加、暫定分は同一要素を書き換え |
| `StatusView` / `Alerts` / `Toast` | 状態表示と通知 |
| `Exporter` | コピー・TXT保存 |
| `App` | 開始フローと全体制御 |

### 話者分離の実装

`_startSelfEngine` / `_startRemoteEngine` がそれぞれ独立した `SpeechRecognition` を持ち、話者ラベルは生成時に固定されます。各エンジンには `SpeechRecognition.start(MediaStreamTrack)` で別々の音声トラックを渡します。

このトラック入力は、未対応ブラウザでは引数が黙って無視され「相手」欄に自分の声が出続けるという誤動作になります。そのため判定用インスタンスに不正な引数を渡し、`TypeError` が投げられるかで対応可否を判定しています。未対応時は相手側エンジンを起動しません。

動作確認用に `?trackInput=on` / `?trackInput=off` で強制指定できます。

### パフォーマンス

- 暫定結果では要素を新規生成せず、既存要素の `textContent` のみ書き換える
- DOM 書き込みは `requestAnimationFrame` に集約（背景タブでは rAF が止まるため `setTimeout` を併走）
- 確定メッセージが300件を超えたら古い行を画面から間引く（保存・コピーには全件含まれます）
- 停止時に `MediaStreamTrack` をすべて `stop()` する

### セキュリティ

認識結果を含むすべてのテキストは `textContent` で扱い、`innerHTML` へは代入しません（XSS 対策）。
